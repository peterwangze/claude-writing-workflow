# 细纲审查

## 执行程序

按以下 10 步机械执行。每一步都必须产出书面结果。

### 第一步：加载文件

打开以下文件，确认全部可读取：
- `06-chapter-outlines/` 下所有细纲文件
- `05-outline.md`
- `17-continuity/story-bible.md`
- `17-continuity/` 下所有 context card 文件
- `workflow-state.json`（获取目标平台）

### 第二步：逐章对照大纲

1. 打开 `05-outline.md` 的 `## 分卷大纲` → 找到当前章对应的章节规划
2. 打开每章细纲的 `## 章节概要`
3. 逐章对比：细纲的概要是否与大纲规划一致？
4. 偏离章数 → 填入 `[___] 章`
5. 每章偏离 → 扣 10 分

### 第三步：检查 Context Card 连

1. 打开第 1 章的 context card → 读 `## 本章结束状态`
2. 打开第 2 章的 context card → 读 `## 本章输入状态`
3. 对比：第 1 章的输出是否 = 第 2 章的输入？
4. 逐对检查所有相邻章 → 断裂处数 → 填入 `[___]`
5. 每处断裂 → 扣 10 分

### 第四步：检查 Bible 合规

1. 打开 `story-bible.md` 的 `## 不可变更事实`
2. 逐条搜索所有细纲文件——该事实是否被违反？
3. 违反处数 → 填入 `[___]` 
4. 每处违反 → 扣 15 分（这是致命项）

### 第五步：数钩子

1. 逐章打开细纲，找到 `## 章末钩子` 和 `**钩子强度**`
2. 记录每章的钩子强度：[强/中/弱/无]
3. 统计前 5 章的强钩子数 → 填入 `[___]/5`（要求 ≥4）
4. 识别连续 3 章弱钩子/无钩子的段落 → 填入 `[第X-Y章]`
5. 每段连续弱钩子 → 扣 10 分

### 第六步：检查付费转化设计

1. 找到付费起始章（来自大纲的付费策略预设）
2. 打开该章细纲 → 检查是否有 `## 付费转化设计` 章节
3. 是否有钩子类型标注？→ 是/否
4. 是否有预期转化强度标注？→ 是/否
5. 缺任一 → 扣 10 分

### 第七步：检查字数规划

1. 打开 `workflow-state.json` → 读取 `project_info.platform`
2. 对照平台字数标准：起点 2500-3000，番茄 2000-2500，晋江 3000-4000
3. 逐章检查细纲的 `字数目标` 是否在范围内
4. 偏差章数 → 填入 `[___]`
5. 偏差 >20% 的章数 → 每章扣 3 分

### 第八步：检查爽点分布

1. 逐章读 `## 爽点设计`
2. 统计每章爽点类型
3. 识别连续无爽点章节 → 填入 `[第X-Y章，共Z章连续无爽点]`
4. 连续 ≥5 章无爽点 → 扣 10 分

### 第九步：情绪曲线预判

1. 逐章读 `## 章末钩子` 的强度标注
2. 按章节顺序排列钩子强度，生成强度序列（如：强-强-中-强-弱-强...）
3. 识别连续 3 章同一强度（尤其是"中-中-中"或"弱-弱-弱"）→ 填入 `[第X-Y章]`
4. 每段连续同一强度 → 扣 5 分

### 第十步：逐项计分

| 步骤 | 检查项 | 满分 | 扣分 | 得分 |
|------|--------|------|------|------|
| 2 | 大纲一致性 | 15 | | |
| 3 | Context Card 连 | 15 | | |
| 4 | Bible 合规 | 15 | | |
| 5 | 钩子强度 | 15 | | |
| 6 | 付费转化设计 | 10 | | |
| 7 | 字数规划 | 10 | | |
| 8 | 爽点分布 | 10 | | |
| 9 | 情绪曲线 | 10 | | |
| **总分** | | **100** | | **[___]/100** |

## 判定

| 总分 | 判定 |
|------|------|
| ≥90 | ✅ 通过 |
| <90 | 🚫 不通过——必须修改后重审 |
