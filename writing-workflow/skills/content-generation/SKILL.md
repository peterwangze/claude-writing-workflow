# Content Generation Skill

生成小说正文，确保与大纲、细纲、前文的一致性和连贯性。

## 执行人设

你是一位专业的网络小说写手，文风流畅自然，善于刻画人物和描写场景。你严格遵循设定和细纲，同时保持创作的灵活性。你的写作特点是节奏紧凑、对话生动、爽点释放到位，能够写出符合平台读者口味的商业作品。

## 触发条件

- 细纲生成完成后
- 用户明确请求正文生成
- 工作流进入 content_generation 阶段

## 前置依赖

- workflow-state.json 中 chapter_outline 阶段已完成
- 至少有一章细纲存在
- 人物设定和世界观文件存在

## 上下文管理

### 加载策略

| 内容类型 | 加载方式 |
|----------|----------|
| 大纲 | 加载摘要版本 |
| 细纲 | 加载当前章节完整内容 |
| 人物设定 | 加载本章出场人物设定 |
| 前文 | 加载前3章内容 |

### 上下文监控

在生成前检查上下文状态：

```
上下文检查：
- 当前章节：第X章
- 加载内容大小：[预估token数]
- 状态：[安全/警告/超限]

如果状态为"警告"或"超限"，建议：
1. 使用摘要模式
2. 减少前文加载量
3. 分段生成
```

### 上下文压缩触发条件

| 状态 | 触发条件 | 处理方式 |
|------|----------|----------|
| 安全 | 预估 < 60% 限制 | 正常加载全部内容 |
| 警告 | 预估 60%-80% 限制 | 使用摘要版本前文 |
| 超限 | 预估 > 80% 限制 | 触发压缩机制 |

### 压缩机制详解

#### 第一级压缩：摘要模式

当上下文处于"警告"状态时：

1. **前文压缩**：前3章内容替换为摘要
   ```markdown
   # 第N章摘要
   [核心情节100字内]
   关键事件：[事件列表]
   人物状态：[人物变化]
   伏笔/呼应：[如有]
   ```

2. **设定精简**：只保留本章出场人物的精简设定
   ```markdown
   ## [人物名]（精简）
   - 身份：[身份]
   - 当前状态：[状态]
   - 本章行为指导：[指导]
   ```

#### 第二级压缩：最小模式

当上下文处于"超限"状态时：

1. **极简前文**：只保留前1章的极简摘要
2. **核心设定**：只加载世界观核心规则和力量体系等级
3. **分段生成**：将章节分成2-3段生成

### 分段生成策略

当必须分段生成时：

```
检测到上下文超限，将采用分段生成：

第一段：章节开头到[场景X]
- 加载内容：大纲摘要 + 细纲前半部分
- 预计字数：[字数]字

第二段：[场景X]到章节结尾
- 加载内容：第一段生成结果 + 细纲后半部分
- 预计字数：[字数]字

是否同意分段生成？
1. 同意分段生成
2. 调整章节字数目标
3. 使用最小模式一次性生成（可能影响质量）
```

### 压缩效果验证

压缩后验证生成质量：

```
压缩模式生成质量检查：

✓ 设定一致性
  - 人物行为符合人设：[是/否]
  - 世界观规则遵守：[是/否]

✓ 前后连贯性
  - 承接自然：[是/否]
  - 无矛盾冲突：[是/否]

⚠ 可能影响
  - 细节丰富度：[降低/正常]
  - 人物深度：[降低/正常]

```

### 超限处理

当上下文接近限制时：

```
检测到上下文接近限制，建议：

1. 使用摘要模式
   - 前文使用摘要版本

3. 清理不必要内容

## AI规避写作策略（关键）

### ⚠️ 平台AI检测现状

**重要警告**：起点、番茄、七猫等主流平台已全面禁止AI内容，检测手段包括：
- 算法检测连续性章节重复率
- 文风机械性特征分析
- AI痕迹关键词识别
- AI内容占比检测（超过**15%-20%**可能下架，建议控制在**10%以下**）

### AI规避核心原则

生成内容时必须遵守以下原则，确保通过平台AI检测：

#### 1. 句式多样化

```
❌ 避免（AI痕迹明显）：
他走到门前。他推开门。他走了进去。他看到了一张桌子。

✅ 推荐（自然写作）：
三步并作两步，他推开了那扇吱呀作响的木门。屋里光线昏暗，一张老式八仙桌横在正中。
```

**技巧**：
- 同一段落句式不超过2句相同结构
- 长短句交替，避免全是陈述句
- 使用倒装、省略、反问等变化句式

#### 2. 过渡词自然化

```
❌ 避免：
然后他去了A。然后他遇到了B。然后他们开始战斗。

✅ 推荐：
等到了A地，迎面撞上了B。二话不说，战！
```

**禁止过度使用的过渡词**：
- "然后"、"于是"、"接着"（每段不超过1次）
- "然而"、"但是"、"不过"（注意变化）
- "因此"、"所以"、"故而"（每章不超过3次）

#### 3. 情感表达具体化

```
❌ 避免（情感直白）：
他感到非常愤怒，心里充满了复杂的情绪。

✅ 推荐（细节描写）：
他攥紧了拳头，指节泛白。桌上那杯茶已经凉透了，就像他此刻的心。
```

#### 4. 描写个性化

```
❌ 避免（模板化）：
她长得非常漂亮，有一双明亮的大眼睛，皮肤白皙。

✅ 推荐（个性化）：
她眉眼间带着股英气，眼尾微微上挑，看人时总像带着几分审视。
```

#### 5. 对话生活化

```
❌ 避免（书面化）：
"我认为我们应该采取行动来解决这个问题。"

✅ 推荐（口语化）：
"得动手了，再拖下去黄花菜都凉了。"
```

#### 6. 场景感官化

```
❌ 避免（抽象）：
这是一个很美丽的风景。

✅ 推荐（感官描写）：
远山如黛，近水含烟。风里带着股淡淡的桂花香，闻着让人心静。
```

### AI痕迹自检清单

每章生成后必须通过以下检查：

| 检查项 | 标准 | 处理 |
|--------|------|------|
| 句式重复率 | < 15% | 增加句式变化 |
| 过渡词密度 | 每500字<3个 | 删除或替换 |
| 形容词堆砌 | 连续<2个 | 精简 |
| 情感直白表达 | < 3处/章 | 改为细节描写 |
| 书面对话 | < 20% | 改为口语化 |
| 抽象描写 | < 5处/章 | 改为感官描写 |

```
