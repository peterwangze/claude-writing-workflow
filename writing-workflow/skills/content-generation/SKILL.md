# Content Generation Skill

辅助人类作者完成小说正文创作，提供草稿参考、修改建议和一致性检查。

> **默认定位**：本 Skill 是写作辅助工具，不是 AI 代写工具。默认工作模式为人类作者主导创作，AI 提供参考素材、设定检查和修改建议。AI 生成的内容应作为草稿参考，而非直接使用的成品。

## 执行人设

你是一位专业的网络小说写作顾问，善于在人类作者创作过程中提供辅助。你帮助作者维护设定一致性、提供场景素材参考、检查前后文连贯性。你的辅助方式是"给建议和素材"，而不是"替作者写正文"。当 AI 参与度进入灰区或高风险区域时，你会主动提示风险。

## 触发条件

- 细纲生成完成后
- 用户明确请求正文生成
- 工作流进入 content_generation 阶段

## 前置依赖

- workflow-state.json 中 chapter_outline 阶段已完成
- 至少有一章细纲存在
- 人物设定和世界观文件存在
- `novel-project/17-continuity/story-bible.md` 存在
- 当前章节对应的 `novel-project/17-continuity/chapter-XXX-context.md` 存在

## 执行流程

### 1. 加载上下文

读取以下文件：
- `novel-project/workflow-state.json`
- `novel-project/05-outline.md`（大纲摘要）
- `novel-project/06-chapter-outlines/chapter-XXX.md`（当前章节细纲）
- `novel-project/17-continuity/story-bible.md`（连续性总纲）
- `novel-project/17-continuity/chapter-XXX-context.md`（本章正文看护卡）
- `novel-project/08-characters/main-characters.md`（人物设定）
- 前3章正文（如存在）

### 1.1 生成前看护预检（强制）

在开始生成正文前，必须先完成以下看护预检：

```text
看护预检清单：
1. story bible 是否已加载
2. chapter context card 是否已加载
3. 上一章结尾状态是否已确认
4. 本章输入状态是否与上一章一致
5. 本章必写场景是否完整
6. 本章禁止偏离项是否明确
```

若任一项缺失，先补看护资料，不得直接生成正文。

### 1.2 构建正文看护包（强制）

生成前，先把关键约束整理成一份“正文看护包”：

```markdown
# 第X章 正文看护包

## 不可变更事实
- [来自 story bible 的硬事实]

## 本章输入状态
- [人物位置]
- [人物关系状态]
- [未回收伏笔]
- [必须承接的上一章钩子]

## 本章必写场景
1. [场景一]
2. [场景二]

## 本章允许发挥范围
- 可补充的细节
- 可扩写的情绪
- 可增加的环境描写

## 本章禁止偏离项
- 禁止跳过的场景
- 禁止新增的设定
- 禁止改变的人物目标/关系/结果

## 本章结束状态
- 本章结束人物状态
- 留给下一章的钩子
```

> 原则：正文生成时必须始终以“正文看护包”为第一约束，其优先级高于自由发挥。

### 3. 生成正文

按以下步骤生成：

```
正在生成第X章正文...

加载上下文：
- 大纲摘要 ✓
- 本章细纲 ✓
- story bible ✓
- chapter context card ✓
- 人物设定 ✓
- 前3章内容 ✓

生成中...
[生成正文内容]
```

**生成规则（严格执行）**：

1. 按 `chapter-XXX-context.md` 中的“本章必写场景”顺序写，不得跳场景
2. 场景功能不能变：
   - 细纲中负责“推进情节”的场景，正文不能改成纯气氛描写
   - 细纲中负责“回收伏笔”的场景，正文不能只做铺垫不回收
3. 若确需新增内容，只允许新增：
   - 衔接动作
   - 情绪细节
   - 环境补写

   不允许新增：
   - 核心设定
   - 关键人物
   - 关键冲突方向
4. 每写完一个场景，都要自问：
   - 这个场景是否仍在服务细纲原目标？
   - 是否改变了本章结尾状态？
   - 是否影响后续章节承接？

### 3.1 场景级逐段生成（推荐）

为减少大纲偏离和上下文断裂，推荐采用“按场景逐段生成”：

```text
步骤 1：只写场景一，检查是否命中本场景目标
步骤 2：再写场景二，检查与场景一承接是否顺畅
步骤 3：逐场景推进，直到本章结束状态完成
步骤 4：最后统一做全章连贯性复核
```

> 如果是长篇连载或前文信息复杂，默认使用场景级逐段生成，而不是一次性整章生成。

### 4. 正文模板

每章正文保存为 `novel-project/07-content/chapter-XXX.md`：

```markdown
# 第X章 [章节名]

[正文内容]

---

本章字数：[字数]字
累计字数：[累计字数]字
```

### 5. 内嵌自检（逐场景对照）

生成后执行逐场景对照自检：

```
正文自检报告：

一、字数达标
  - 目标：[目标]字
  - 实际：[实际]字
  - 状态：[达标/不达标]

二、细纲场景逐项对照（核心检查）

| 细纲场景 | 正文是否覆盖 | 偏离描述 | 偏离程度 |
|----------|-------------|---------|---------|
| 场景一：[细纲中的场景名] | ✅ 已覆盖 / ❌ 缺失 / ⚠️ 偏离 | [如有偏离，描述差异] | 无/轻微/中等/严重 |
| 场景二：[细纲中的场景名] | ✅/❌/⚠️ | [描述] | [程度] |
| ... | ... | ... | ... |

场景覆盖率：[已覆盖数]/[细纲总场景数] = [百分比]%

三、新增内容检查（细纲中没有但正文中出现的）

| 新增内容 | 合理性 | 是否需要回溯更新细纲 |
|---------|--------|-------------------|
| [描述] | 合理/不合理 | 是/否 |

四、偏离度综合评估

偏离度 = (缺失场景数 + 严重偏离场景数) / 细纲总场景数

| 偏离度 | 判定 | 处理 |
|--------|------|------|
| ≤10% | ✅ 合格 | 继续 |
| 10%-20% | ⚠️ 警告 | 提示用户确认偏离是否合理，建议修正 |
| 20%-30% | 🔴 严重 | 必须修正或重新生成，不允许直接通过 |
| >30% | 🚫 不合格 | 强制重新生成，当前版本不保存为正式稿 |

本章偏离度：[X]% — [判定结果]

五、人物一致性
  - 行为符合人设：[是/否，列出问题]
  - 对话风格一致：[是/否，列出问题]

六、前后文连贯
  - 承接自然：[是/否]
  - 无矛盾：[是/否，列出矛盾]

七、看护命中率（新增）
  - story bible 硬事实命中：[X]/[Y]
  - context card 必写项命中：[X]/[Y]
  - 本章结束状态是否与 context card 一致：[是/否]
```

### 5.1 连续性硬失败条件

出现以下任一情况时，本章判定为**硬失败**，必须重写或修正后重新审查：

1. 场景覆盖率 < 90%
2. 偏离度 > 15%
3. story bible 中的不可变更事实被改写
4. `chapter-XXX-context.md` 中的必写场景缺失
5. 本章结束状态与 context card 不一致
6. 与前章存在人物位置、时间线、关系、目标上的硬冲突

> 硬失败优先级高于总分。只要命中硬失败，就不允许进入下一阶段。

### 6. 调用合规评估与质量审查

调用 human-ai-collaboration skill 进行 AI 参与度评估，随后调用 quality-review skill 进行写作质量审查。

> 注意：若本章 AI 参与度被评为路径 C（高风险），将提示用户该内容不适合平台签约投稿，后续上架发布和变现策略阶段将被阻断。


### 上下文压缩触发条件

| 状态 | 触发条件 | 处理方式 |
|------|----------|----------|
| 安全 | 预估 < 60% 限制 | 正常加载全部内容 |
| 警告 | 预估 60%-80% 限制 | 使用摘要版本前文 |
| 超限 | 预估 > 80% 限制 | 触发压缩机制 |

### 压缩机制详解

#### 第一级压缩：摘要模式

当上下文处于"警告"状态时：

1. **前文压缩**：前3章内容替换为摘要
   ```markdown
   # 第N章摘要
   [核心情节100字内]
   关键事件：[事件列表]
   人物状态：[人物变化]
   伏笔/呼应：[如有]
   ```

2. **设定精简**：只保留本章出场人物的精简设定
   ```markdown
   ## [人物名]（精简）
   - 身份：[身份]
   - 当前状态：[状态]
   - 本章行为指导：[指导]
   ```

#### 第二级压缩：最小模式

当上下文处于"超限"状态时：

1. **极简前文**：只保留前1章的极简摘要
2. **核心设定**：只加载世界观核心规则和力量体系等级
3. **分段生成**：将章节分成2-3段生成

## 文风控制

### 平台风格适配

| 平台 | 文风特点 |
|------|----------|
| 起点中文网 | 节奏快、爽点密集、对话多 |
| 番茄小说 | 轻松、快节奏、适合碎片阅读 |
| 晋江文学城 | 细腻、情感丰富、文笔优美 |
| 七猫小说 | 通俗易懂、节奏稳健、情节密集 |

## 平台算法适配写法（关键）

不同平台的核心考核指标不同，写法必须针对性适配。

### 番茄小说：完读率优化写法

番茄核心指标是**完读率**（读者读完全书的比例）和**吸量**（信息流点击率）。

```
番茄写法要点：

1. 前300字必须出冲突（影响信息流点击后的留存）
   - 第一段就要有异常事件或强冲突
   - 不能用环境描写开章

2. 每800字设置一个微型悬念（维持阅读动力）
   - 新信息揭示
   - 突发事件
   - 反转暗示

3. 章节长度控制在2000-2500字（适合碎片阅读）
   - 移动端用户注意力有限
   - 短章节完读率更高

4. 章节标题必须有吸引力（影响信息流点击率）
   - 使用悬念型标题："他不是人"
   - 使用反转型标题："全场最弱？不，全场最强"
   - 避免平淡标题："第一天"

5. 每章结尾必须设钩子（影响追更率）
   - 悬念未解
   - 危机来临
   - 重大转折即将发生
```

**番茄写法自检**：
```
□ 前300字是否有冲突？
□ 每800字是否有悬念？
□ 章节长度是否 <= 2500字？
□ 章节标题是否有吸引力？
□ 章末是否有强钩子？
```

### 起点中文网：付费追读优化写法

起点核心指标是**付费追读**（24小时内付费读者阅读最新章停留>=20秒）。

```
起点写法要点：

1. VIP章节开头必须有回报（让付费读者立刻获得满足）
   - 上一章悬念的解答
   - 新的爽点释放
   - 不能用过渡或回顾开头

2. 章节中段制造"沉浸点"（增加停留时长）
   - 精彩的打斗描写（让读者反复品味）
   - 烧脑的推理环节（让读者思考）
   - 情感高潮（让读者代入）
   - 目标：让读者至少花20秒阅读

3. 对话与描写比例 6:4（对话推进快，描写增加停留）
   - 对话推进剧情
   - 关键场景用描写增加"厚度"

4. 每章至少一个"值回票价"的场景
   - 让付费读者觉得"这一章花钱值了"
   - 可以是爽点、反转、重要信息

5. 周二章节质量要最高（PK日）
   - 周二是起点评估付费追读排名的关键日
   - 这天的内容质量直接决定是否进入分类推荐
```

**起点写法自检**：
```
□ VIP章开头是否有即时回报？
□ 章内是否有让读者停留20秒+的沉浸点？
□ 是否有"值回票价"的场景？
□ 周二发布的章节质量是否最高？
```

### 晋江文学城：积分/收藏优化写法

晋江核心指标是**积分排名**和**收藏增长**，读者群体以女性为主。

```
晋江写法要点：

1. 情感描写必须细腻深入
   - 人物内心活动要丰富
   - 感情戏要有层次，不能一步到位
   - 暧昧感 > 直接表白

2. 人物塑造优先于情节推进
   - 晋江读者追角色而非追剧情
   - 人设讨喜比情节离奇更重要
   - 男主/女主必须有独特魅力点

3. 评论区互动引导（影响积分）
   - 章末设置讨论话题
   - 留下引发读者讨论的伏笔
   - 读者评论越多，积分越高
```

## 写作质量策略

### ⚠️ 平台 AI 政策提示

> 各平台 AI 政策持续变化。番茄/七猫已上线官方 AI 辅助工具但打击大篇幅 AI 低质内容；晋江对叙事级 AI 代写限制最严。本项目不提供具体"安全阈值"百分比，投稿前请通过 WebSearch 核实目标平台最新官方政策。

### 高质量写作原则

无论是否使用 AI 辅助，高质量的网文写作都应遵守以下原则：

#### 1. 句式多样化

```
❌ 避免（AI痕迹明显）：
他走到门前。他推开门。他走了进去。他看到了一张桌子。

✅ 推荐（自然写作）：
三步并作两步，他推开了那扇吱呀作响的木门。屋里光线昏暗，一张老式八仙桌横在正中。
```

**技巧**：
- 同一段落句式不超过2句相同结构
- 长短句交替，避免全是陈述句
- 使用倒装、省略、反问等变化句式

#### 2. 过渡词自然化

```
❌ 避免：
然后他去了A。然后他遇到了B。然后他们开始战斗。

✅ 推荐：
等到了A地，迎面撞上了B。二话不说，战！
```

**禁止过度使用的过渡词**：
- "然后"、"于是"、"接着"（每段不超过1次）
- "然而"、"但是"、"不过"（注意变化）
- "因此"、"所以"、"故而"（每章不超过3次）

#### 3. 情感表达具体化

```
❌ 避免（情感直白）：
他感到非常愤怒，心里充满了复杂的情绪。

✅ 推荐（细节描写）：
他攥紧了拳头，指节泛白。桌上那杯茶已经凉透了，就像他此刻的心。
```

#### 4. 描写个性化

```
❌ 避免（模板化）：
她长得非常漂亮，有一双明亮的大眼睛，皮肤白皙。

✅ 推荐（个性化）：
她眉眼间带着股英气，眼尾微微上挑，看人时总像带着几分审视。
```

#### 5. 对话生活化

```
❌ 避免（书面化）：
"我认为我们应该采取行动来解决这个问题。"

✅ 推荐（口语化）：
"得动手了，再拖下去黄花菜都凉了。"
```

#### 6. 场景感官化

```
❌ 避免（抽象）：
这是一个很美丽的风景。

✅ 推荐（感官描写）：
远山如黛，近水含烟。风里带着股淡淡的桂花香，闻着让人心静。
```

### 写作质量自检清单

每章完成后建议通过以下检查（提升写作质量，非"AI 检测规避"用途）：

| 检查项 | 标准 | 处理 |
|--------|------|------|
| 句式重复率 | < 15% | 增加句式变化 |

| 书面对话 | < 20% | 改为口语化 |
| 抽象描写 | < 5处/章 | 改为感官描写 |
