# SKILL 架构原则

## 核心原则

1. **一个 SKILL = 一件事**。专业、可重复、不依赖 LLM 能力波动。
2. **一个角色可对应多个 SKILL**。Agent 在不同阶段加载不同 SKILL。
3. **SKILL 是程序，不是散文**。给定相同输入，不同 LLM 应产出可比结果。

## 当前问题

| 问题 | 表现 |
|------|------|
| quality-review 做太多事 | 9 维度从设定逻辑到 AI 痕迹全部塞在一起，审查员不知道重点 |
| SKILL 是散文不是程序 | "检查人物一致性" → LLM 自己判断什么叫一致性。不稳定 |
| 审查和生产混在一起 | chapter-outline 既生成细纲又自检，同一个人当运动员又当裁判 |

## 整改方向

1. quality-review 拆分为独立审查 SKILL（每维度一个）
2. 每个 SKILL 改为机械可执行步骤（Step 1/2/3 格式）
3. 审查 SKILL 与生产 SKILL 完全分离
